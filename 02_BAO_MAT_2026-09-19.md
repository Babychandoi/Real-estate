# Đánh giá bảo mật

Snapshot: [`b8d66bf`](https://github.com/Babychandoi/Real-estate/commit/b8d66bf251c117b2775a6b586a55ea8262ccaaff) — 2026-09-19

## Kết luận

Nền tảng bảo mật có nhiều lựa chọn đúng: BCrypt cost 12, opaque bearer session được lưu dạng hash, token reset/xác minh có hạn và dùng một lần, mã hóa PII AES-GCM, blind index HMAC, kiểm tra file theo magic bytes + MIME + ClamAV, tài liệu KYC private và production guardrails.

Tuy nhiên, snapshot này **không nên public launch**. Một endpoint anonymous có thể làm ẩn tin; public CMS có thể lộ draft; admin không có MFA; audit chain có race/fail-open; rate limit tin header do client điều khiển. Main branch không bảo vệ và security scan bị skip khi E2E lỗi.

## Phát hiện trọng yếu

### SEC-01 — Critical: public report có thể tự động ẩn bất kỳ tin đang hoạt động

Chuỗi khai thác không yêu cầu đăng nhập:

1. Security cho phép `POST /api/v1/public/reports` anonymous.
2. Request nhận enum `severity` từ client; controller chuyển nguyên giá trị vào service.
3. Nếu `P0_EMERGENCY`, service gọi `listing.pause()` ngay.

Bằng chứng:

- [`SecurityConfig.java` dòng 55–76](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/shared/security/SecurityConfig.java#L55-L76)
- [`ViolationReportController.java` dòng 35–48](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/lead/api/ViolationReportController.java#L35-L48)
- [`ViolationReportApplicationService.java` dòng 45–63](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/lead/application/ViolationReportApplicationService.java#L45-L63)

Tác động: đối thủ, bot hoặc botnet có thể làm gián đoạn marketplace. Rate limit 30/phút/IP không đủ, và hiện còn có thể spoof header IP nếu backend bị truy cập trực tiếp.

Sửa bắt buộc:

- Bỏ `severity` khỏi DTO public; server gán `MEDIUM` hoặc `UNTRIAGED`.
- Chỉ moderator hoặc rules engine có tín hiệu đủ mạnh mới nâng P0/ẩn khẩn cấp.
- CAPTCHA/risk score, fingerprint, duplicate/coalescing và quota theo listing/account/network.
- Ghi audit đầy đủ quyết định tự động; alert khi report spike.

### SEC-02 — High: API CMS public làm lộ revision chưa xuất bản

Controller lọc bài public nhưng sau đó lấy toàn bộ revisions, chọn revision mới nhất làm `currentRevision` và trả luôn mảng `revisions`. Nếu bài đã publish có một draft/rejected mới hơn, anonymous response chứa nội dung đó.

Bằng chứng:

- [`CmsArticleController.java` dòng 99–123](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/cms/api/CmsArticleController.java#L99-L123)
- [`ArticleResponse.java` dòng 26–41](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/cms/api/response/ArticleResponse.java#L26-L41)

Sửa bắt buộc: tạo `PublicArticleResponse` riêng, chỉ truy vấn revision có id bằng `publishedRevisionId`; không serialize review metadata hoặc revision list; thêm regression test “published + newer draft”.

### SEC-03 — High: admin không có MFA/step-up

Admin có route/login riêng và server kiểm tra role, nhưng request chỉ gồm email/password. Lịch sử commit cho thấy MFA từng được thêm rồi bị xóa. Các tác vụ nhạy cảm như KYC approval, billing reconciliation, moderation và CMS publish không có step-up.

Bằng chứng:

- [`AuthController.java` dòng 58–60](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/iam/api/AuthController.java#L58-L60)
- [`_admin.login.tsx`](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/frontend/app/routes/_admin.login.tsx)
- Commit thêm rồi bỏ MFA: [`b6a6972`](https://github.com/Babychandoi/Real-estate/commit/b6a6972) và [`7a8d82b`](https://github.com/Babychandoi/Real-estate/commit/7a8d82b)

Sửa: WebAuthn/passkey hoặc TOTP với recovery codes; step-up TTL ngắn cho KYC/billing/publish; session admin tách audience và ngắn hơn session user; alert đăng nhập bất thường.

### SEC-04 — High: tính toàn vẹn đơn hàng không dựa trên snapshot

Khi tạo order, code lưu tên/quota/thời hạn gói và tài khoản ngân hàng vào các cột snapshot. Nhưng truy vấn order lại join singleton `bank_settings` hiện tại để tạo QR; approve tìm plan hiện tại theo code và cấp quota/thời hạn hiện tại. Admin đổi bank hoặc plan sau lúc khách đặt sẽ thay đổi nghĩa của đơn cũ.

Bằng chứng: [`BillingService.java` dòng 34–52 và 77–79](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/billing/BillingService.java#L34-L79).

Sửa: order read model phải chứa và dùng toàn bộ snapshot; invoice/grant dựa trên snapshot; ghi currency/price/quota/duration/bank immutable; test thay đổi plan/bank giữa create và approve.

### SEC-05 — High: audit chain không an toàn dưới concurrency và fail-open

Mỗi request đọc “hash mới nhất” rồi insert. Hai request đồng thời có thể đọc cùng một hash và tạo hai nhánh. Không có sequence/row lock/serializable transaction. Mọi exception bị bắt và nghiệp vụ vẫn thành công. Filter chỉ audit mutation và GET reveal contact, không audit staff đọc KYC.

Bằng chứng: [`AuditTrailFilter.java` dòng 28–52](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/shared/security/AuditTrailFilter.java#L28-L52).

Sửa:

- Dùng monotonically increasing sequence + unique predecessor hoặc transactional advisory lock.
- Gửi bản sao tới append-only/WORM store và ký checkpoint ngoài DB.
- Audit principal, tenant/resource id, purpose, result; không ghi secret/PII thô.
- Với tác vụ high-risk, outbox bắt buộc hoặc fail-closed có kiểm soát; alert mọi write failure.
- Audit cả KYC document reads, billing approve/reject và permission change.

### SEC-06/07 — High/Medium: appeal sai quyền và resume thiếu kiểm tra report khác

Toàn bộ `/api/v1/reports/**` chỉ cho ADMIN/MODERATOR, trong khi endpoint/comment nói broker/chủ tin gửi appeal. Service appeal không nhận actor nên không thể kiểm tra ownership. Ngược lại, nếu chỉ nới SecurityConfig sẽ tạo IDOR. Khi dismiss với `resumeListing=true`, service resume trực tiếp mà không kiểm tra các P0/open reports khác.

Bằng chứng:

- [`SecurityConfig.java` dòng 66–73](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/shared/security/SecurityConfig.java#L66-L73)
- [`ViolationReportController.java` dòng 108–134](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/lead/api/ViolationReportController.java#L108-L134)
- [`ViolationReportApplicationService.java` dòng 108–126](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/lead/application/ViolationReportApplicationService.java#L108-L126)

Sửa: endpoint owner-scoped riêng; resolve report → listing → owner và so với actor; moderator endpoint riêng. Resume chỉ khi không còn hold/report/quyết định khóa hiệu lực.

### SEC-08 — Medium: rate limit phụ thuộc header không tin cậy

Filter lấy `X-Real-IP` nếu có mà không xác minh request đến từ reverse proxy tin cậy. Nếu backend lộ trực tiếp, caller thay header để né giới hạn. Login chỉ bị giới hạn theo IP/path, không theo email/account/device; Redis lỗi thì fallback theo từng pod.

Bằng chứng: [`RequestRateLimitFilter.java` dòng 27–64](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/shared/security/RequestRateLimitFilter.java#L27-L64).

Sửa: xóa/overwrite proxy headers tại edge; chỉ đọc forwarded headers từ CIDR tin cậy; limit kết hợp IP + normalized account + device; exponential backoff/risk signals; Redis cluster/managed rate limiting cho production.

### SEC-09 — Medium: staff đọc KYC không step-up và không audit

Chính chủ phải nhập lại mật khẩu và nhận grant 10 phút. ADMIN/MODERATOR được bypass grant khi đọc object KYC, và audit filter không coi GET KYC là sensitive read.

Bằng chứng: [`MediaController.java` dòng 45–55](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/media/MediaController.java#L45-L55).

Sửa: staff step-up + purpose/reason + case id; least privilege role riêng; audit read; watermark/short-lived access; review bất thường.

### SEC-10 — Medium: CMS role và HTML

Cả ADMIN và MODERATOR có thể tạo, submit, approve/reject; service không chứng minh người duyệt khác người tạo. `contentHtml` được lưu nguyên trạng, chưa có sanitizer. Hiện frontend public chưa render bài, nhưng đây là stored-XSS debt khi route được nối.

Sửa: RBAC `AUTHOR/REVIEWER/PUBLISHER`, four-eyes rule nếu nội dung pháp lý; sanitize server-side bằng allowlist và CSP; test payload XSS.

### SEC-11 — Medium: supply-chain gate chưa cưỡng chế

GitHub trả `protected: false` cho `main`; commit HEAD unsigned. CI là một job tuyến tính. Trivy nằm sau Playwright nên bị skip khi E2E fail. Tại snapshot, [run 57](https://github.com/Babychandoi/Real-estate/actions/runs/35048152964) đỏ và security scan không tạo kết quả.

Bằng chứng: [`.github/workflows/ci.yml` dòng 11–50](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/.github/workflows/ci.yml#L11-L50).

Sửa: branch protection/ruleset; PR review; required backend/frontend/E2E/security checks; tách Trivy/SBOM/secret scan thành job độc lập; pin actions bằng full SHA; ký artifact/image và provenance.

### SEC-12 — Medium: code giao dịch dormant vẫn chứa xác thực giả

Production validator đang chặn bật giao dịch thật — đây là điểm tốt. Tuy nhiên service vẫn hardcode số người bán và coi mọi chuỗi dài sáu ký tự là OTP hợp lệ. Chỉ cần guard bị cấu hình sai hoặc code được tái sử dụng là rủi ro trở lại.

Bằng chứng: [`DepositTransactionApplicationService.java` dòng 60–95](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/transaction/application/DepositTransactionApplicationService.java#L60-L95).

Sửa: xóa/cách ly module khỏi production artifact; chỉ bật lại sau provider integration, nonce/challenge binding, expiry, attempt limit, replay protection và audit.

## Kiểm soát tốt đã xác nhận

- BCrypt cost 12: [`SecurityConfig.java` dòng 84](https://github.com/Babychandoi/Real-estate/blob/b8d66bf251c117b2775a6b586a55ea8262ccaaff/backend/src/main/java/com/company/bds/shared/security/SecurityConfig.java#L84).
- Stateless bearer header phù hợp với CSRF disabled; token phiên ngẫu nhiên và lưu hash.
- Password reset token 30 phút, one-time; reset thu hồi active sessions.
- PII dùng AES-GCM + blind index HMAC; production fail-fast nếu khóa thiếu/yếu.
- Upload giới hạn 10 MB, kiểm tra content signature/MIME, quét ClamAV fail-closed, KYC private.
- Media cleanup có kiểm tra tham chiếu; external demo image host bị từ chối ở production.
- Security headers backend và CSP Nginx đã được cấu hình; public assets có cache immutable.
- Production validator không cho bật “real KYC/transactions” chưa tích hợp.

## Tiêu chí đóng báo cáo

Không coi là “đã sửa” chỉ vì UI che trường hoặc route. Mỗi finding cần:

- test server-side chứng minh unauthorized/abusive request bị chặn;
- integration test cho state transition và concurrency nếu liên quan;
- evidence từ CI bắt buộc trên protected branch;
- logging/metric/alert cho hành vi thất bại hoặc bất thường;
- threat model cập nhật cho report, KYC, billing và CMS.
