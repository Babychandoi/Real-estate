## 3. Contract deviations and extensions (all backward compatible)

1. **Job queue:** added `JobQueue.enqueueOnce(queue, key, payload, runAt)` (e-mail must not repeat after completion; pending coalescing alone cannot guarantee that) and `JobHandler.maxAttempts()` (default 10, stored at enqueue). `bds_enqueue_job` has an optional 5th parameter `p_max_attempts integer DEFAULT 10`; the contract's 3/4-argument calls are unchanged.
2. **Expired leases count as attempts** (a job that repeatedly kills its worker is dead-lettered instead of looping). A failure while a newer change was coalesced still counts; the row keeps the newest payload, and a later enqueue after dead-lettering creates a fresh pending job.
3. **Coalescing keeps the earliest `run_at`** (contract). For reschedulable work (appointment reminders) key the job per version and re-check state in the handler (see follow-ups).
4. **`analytics_events.page_path`** column added (the table in §5 has no column for the web event's `page`); only the path is stored, query string/fragment dropped (they can carry reset tokens or search text).
5. **Consent:** without consent `user_id` is also NULL (contract lists anonymous/session/utm; chose the privacy-preserving reading); missing `consent` = denied.
6. **Stricter ingestion:** web `eventId` must be UUIDv4 (server ids are UUIDv3, so a client cannot pre-empt a server fact); unknown top-level/page/utm fields are rejected; the batch is all-or-nothing; `occurredAt` within [now − 7 days, now + 5 min]; `listingId` required for `listing_detail_viewed` and `lead_form_opened`; required keys per event (e.g. `web_vital` metric + value); `district` digits only, `context` lower-case code; `compare_opened.listingIds` ≤ 48. Response `202 {accepted, duplicates}`, `Cache-Control: no-store`; 413 over 64 KB, 415 for other media types.
7. **Audit trail:** `AuditTrailFilter` skips `POST /api/v1/events` (anonymous telemetry would otherwise let anyone flood the hash-chained audit log).
8. **Mail:** `MailOutbox.enqueue` returns `Optional<UUID>` (empty when deduplicated); `MailMessage.text(...)` helper; envelope sealed via new `PiiProtectionService.seal/unseal` (AES-GCM, purpose as AAD).
9. **Scheduled lock:** overload with `minHold`.
10. **Roles schema:** `chk_user_roles_role` is added `NOT VALID` and validated in the same migration only if every existing row complies (it never blocks the deploy); no unique `(user_id)` constraint because production rows cannot be inspected — effective-role resolution handles several rows.
11. **Trust:** `listing_verifications.decided_by` references `users(id)`. **Leads:** legacy `updated_at` backfilled to `created_at` (no change history exists; `first_response_at` left NULL — no invented timestamps).
12. **Search:** `app.search.elasticsearch.enabled` and `app.search.index-name` added (test opt-in with a prefixed index; production defaults unchanged).
13. **Seeder:** `app.uat-seed.password` (E2E sign-in as synthetic buyer/broker/owner; refused when `app.mode=production`).
14. **Test DB name** `bds_it_<epochSeconds>_<8 hex>` (epoch lets a later run sweep databases left by killed JVMs after 12 h).
15. The owner-side `PATCH /leads/{id}/status` refuses `WITHDRAWN` (only the requester withdraws; endpoint = S3).

## 4. Known gaps (honest)

- **`POST /api/v1/events` has no rate limit yet**: `RequestRateLimitFilter` is S5's (not modified as instructed). Until S5's policy lands the endpoint is bounded only by 50 events / 64 KB per request. S5 should ship before or together with this branch in production.
- Server events are wired only for `lead_submitted` and `listing_published`; the other catalog server events belong to flows that S3/S6 build (favorites, saved searches, first response, qualification, appointments).
- Write paths do not yet fill `legal_status_code`, `furnishing`, rent terms, `project_id`, lead `version/updated_at/first_response_at/qualification`: backfill covers legacy rows only; S3 maps them. New KYC/ownership approvals do not set `expires_at` yet (NULL = no expiry per §6); S4 owns trust decisions.
- Mail delivery is at-least-once: a crash between the SMTP `250` and the completion update resends one message.
- `MediaStorageService.cleanupOrphans` has no dedicated test (needs a MinIO context); the same lock code path is covered by the generic lock tests and the ES sync test.
- CI job `backend-tests` was not run on GitHub (no push allowed); the YAML parses and mirrors `infra/test/compose.yaml` and the local run.
- Migrations were timed on synthetic data only; a rehearsal on a production copy belongs to Review 3/S10. The V013 showcase listings stay `source=DIRECT` (reclassifying production data is a product decision).
- `GlobalExceptionHandler` maps `HttpMediaTypeNotSupportedException` (and other framework 4xx) to 500 — pre-existing, left to S9; the events endpoint answers 415 itself.
- `IMPLEMENTATION_PLANS_HISTORY.md` / `WALKTHROUGHS_HISTORY.md` were not edited: `03_AGENT_RULES.md` reserves them for the orchestrator (this overrides the generic AGENTS.md rule for this programme).

## 5. Production / deploy notes

- **Migrations V027–V029** run automatically (Flyway, one transaction each). Lock/time: ADD COLUMN with constant/STABLE defaults is metadata-only; the STORED generated column rewrites `listing_revisions` once (ACCESS EXCLUSIVE for the rewrite); backfills are single guarded UPDATEs; two `CREATE INDEX` on `listings` block writes for their build (milliseconds at production size). Additive only: the previous image runs against the new schema, so **rollback = redeploy the previous image** (no down migration). Caveat: e-mails still pending in `background_jobs` at rollback are not sent by the old release.
- **All e-mail now goes through the queue.** Keep `APP_JOBS_ENABLED=true` on at least one backend instance or verification/reset/billing mails stop. New optional variables (defaults in `application.yml`; all but the purge cron are listed in `.env.example`): `APP_JOBS_ENABLED`, `APP_JOBS_POLL_MS`, `APP_JOBS_RETRY_BASE`, `APP_JOBS_RETRY_CAP`, `APP_JOBS_COMPLETED_RETENTION`, `APP_JOBS_PURGE_CRON`, `APP_SEARCH_ELASTICSEARCH_ENABLED`, `APP_SEARCH_INDEX_NAME`. None is mapped in `docker-compose.yml` because the defaults are the production values. No secret added.
- **`backend/Dockerfile` builds with `-DskipTests`**: tests need PostgreSQL/Redis/Mailpit and run in the CI job `backend-tests`; make that job a required check (F01.9, EXTERNAL).
- Alerts (for S5): `bds_jobs_dead{queue="email"} > 0`, `bds_jobs_lag_seconds{queue="email"} > 300`. Requeue a dead job after fixing SMTP: `UPDATE background_jobs SET dead_lettered_at = NULL, attempts = 0, run_at = now(), last_error = NULL WHERE id = '<id>';`.
- Local development: `scripts/test-infra.sh up` then `eval "$(scripts/test-infra.sh env)"` before `mvnw verify`.
